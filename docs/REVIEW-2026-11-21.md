# Review of alpha 0.6.0: what is missing (2026-11-21)

Whole-repo read: server, web, deploy scripts, CI, docs. Not committed. Tick items off in `PROGRESS.md` as they get fixed.
**[C]** = confirmed in the code · **[S]** = suspected (needs a test to prove).

## A. Fix first (real risks): all fixed in alpha 0.6.1
1. **[C] Backups can be empty and still look fine.** `deploy/backup-now.sh` and the `backup` service in `docker-compose.yml` pipe `pg_dump | gzip`; `sh` has no `pipefail`, so a failed dump is saved as a "successful" tiny file. `deploy/restore.sh` relies on that same script for its safety backup and then drops the database.
2. **[C] An admin can take over any other account, including `owner` and other admins.** `POST /admin/users/:id/reset-code` (`server/src/admin.ts`) needs no password re-entry (deleting a user does), and it only blocks yourself. Admins can also remove each other.
3. **[C] A 401 does not clear cached data.** `web/src/main.tsx` only clears `['me']`. The next person signing in on that phone briefly sees the previous account's data, and it can end up in their offline kit.
4. **[C] Offline mode skips the PIN lock.** In `web/src/App.tsx`, `OfflineApp` is rendered outside `<AppLock>`.
5. **[C] "12,50" is read as 1250.00.** `web/src/domain/money.ts` strips commas as thousands separators, while the FX-rate field treats a comma as a decimal point. Some Android keyboards type `,` for decimals.
6. **[C] The admin sign-up form can wipe settings.** `SignupCard` (`web/src/pages/Admin.tsx`) starts as "open, no code" and can be saved before the real settings load (or after loading failed). That opens sign-ups and clears the invite code.
7. **[C] A split's "Owed to me" entry can be edited or deleted on its own** (`PUT /loans/:id`, `DELETE /loan-people`). The split then silently breaks.
8. **[C] Anyone can lock an account out of sign-in.** 10 wrong passwords for a username, from any IP, block it for 15 minutes, `owner` included. This is a trade-off: consider a per-IP+account key or a CAPTCHA-free delay.

> Sections B-D: done in alpha 0.6.2 except: 3-decimal currencies, editing a refused offline item, reordering categories/goals, a recurring rule start date in the UI, caps on month/plan rows, faster big restores, `LICENSE` (owner's choice), Dependabot major upgrades (Phase 8).

## B. Should fix (smaller bugs)
- [C] Removing a person deletes their entries (including split ones) with no Undo. Starting a new undo-delete silently drops the previous Undo.
- [C] Receipt quota: an undo restores a receipt without checking the quota, receipts in the trash don't count, and parallel uploads can go over the limit.
- [C] An offline retry at the 50,000-expense cap gets "limit" instead of the already-saved row. A retry while its expense is in the trash creates a duplicate, and the later Undo then fails.
- [C] Reset codes stay valid after the user changes their password.
- [C] `/reset` (erase all data) and `/backup/restore` need no password, unlike delete-account.
- [S] Unexpected database errors are logged in full; Postgres `detail` can contain row values.
- [C] The overpaid-person balance lowers the total owed to others (`outstanding()` in `calc.ts`, the Loans hero).
- [C] The FX rate field doesn't accept Arabic digits. 3-decimal currencies (KWD, JOD) can't be entered correctly.
- [C] `CategoryForm` makes a duplicate category when you retry after the budget save fails.
- [C] Changing the month start day doesn't refresh the compare, weekday and tag reports.
- [C] Lock "Right away" also locks after you come back from the camera or file picker, which loses the open form.
- [C] The offline queue and offline kit stay on the phone after a 401, "sign out everywhere" or account deletion. A refused queued item can only be deleted, not edited or retried.
- [C] Service worker:
  - Opening the app offline right after the first install gives a blank page (hashed assets are not precached).
  - Old assets are never pruned.
  - The "new version" bar stays forever if the web and server versions drift apart (it also shows when the server is *older*).
- [C] The state-load error screen has no Try again button. The Reports year view and the Expenses list have no loading state. The Admin cards have no loading or error states.
- [C] Strings not translated: chart titles in `charts.tsx`, the "Unknown" category, KB/MB sizes in Admin. Two server messages too: "This is not a Budget me backup.", and Zod "field: …" messages.
- [S] Arabic: the minus sign may sit on the wrong side in `KV` rows ("Money left", "Unallocated").
- [C] Accessibility:
  - Sheets have no focus trap and don't return focus on close.
  - Escape closes the sheet under an open confirm dialog.
  - The Budget "More actions" menu doesn't close on touch.
- [S] Backup download isn't one consistent snapshot. A big restore runs one query per row (slow).
- [C] Gaps that need nothing today but are open-ended: `month_budgets` / `category_plans` have no cap, and `sessions`, `audit_log` and `password_resets` grow without cleanup.

## C. Tests missing
- No tests for `PUT /loans/:id`, `PUT /goal-entries/:id`, `POST /budget/:month/clear-plans`, `POST /auth/logout`, or the `/auth/reset` rate limit.
- No cross-account tests for expenses, goals, loans, export or backup (the code is right, but nothing guards it).
- Offline idempotency is only tested with `?force=1`.
